# 自然 Motion

## 先问为什么动

每个动画先回答：

```text
触发原因是什么？
哪个对象在变化？
它从哪里来？
为什么沿这条路径？
为什么在这里停？
用户中途继续操作会怎样？
```

无法回答时，先删除动画再评估。

## 输入驱动与系统驱动

### 输入驱动

拖拽、滑动、缩放等直接操控：

- 对输入变化快速响应。
- 保持运动方向与手势一致。
- 允许速度、位移或惯性在释放后合理延续。
- Snap / magnetic behavior 需要提前可感知，或至少在接近阈值时平滑接管。
- 用户反向操作时立即响应，不等待旧动画结束。

### 系统驱动

页面切换、Overlay、状态变化：

- 运动路径表达空间层级或对象来源。
- 进入、退出不要求镜像曲线。
- 小反馈短促；大型空间变化可以更充分，但不能让用户等。
- 不用 overshoot 证明“用了 Spring”。

## 速度与 easing

Fluent 2 将 natural motion 描述为受 inertia、gravity、weight、velocity 等物理直觉启发，并强调 duration 应考虑对象尺寸与移动距离。

项目转译：

- 使用物理直觉，不做物理仿真竞赛。
- Linear 可用于真实恒定速率，例如持续旋转、进度轨迹或匀速背景流；不要全局禁用。
- Ease-out 常适合用户触发后快速响应并柔和抵达。
- Ease-in 常更适合明确离开的对象，但不机械套用。
- Spring 适合需要连续响应、被打断、拖拽释放或位置追随的关系。

具体 duration / easing / spring token 始终由 `interaction-motion` 决定。

## Causal motion

因果知觉研究显示，简单几何对象只要在时间和空间上满足一定连续条件，人就会自动感到“一个对象导致另一个对象运动”。

UI 启发：

- Trigger 和结果之间减少无意义时间断裂。
- 结果运动方向不要与触发关系冲突。
- 如果 A 操作 B，反馈最好在 A/B 或两者关系附近发生。
- 不要用无关全屏动画把一次局部操作解释成另一个事件。

## Common fate

同步运动很容易被知觉为同组。

- 对同组元素，可以协调运动。
- 对无关对象，避免同频、同向、同速地一起漂移。
- 一个容器重排时，内部元素可以共享主要运动趋势，但不需要每个子元素各自夸张动画。

## Reduced Motion

Reduced Motion 下保留：

- 对象身份。
- 方向/来源的最小线索。
- 状态因果。

可去掉：

- 大幅位移。
- 视差。
- 惯性尾巴。
- 明显 overshoot / bounce。
