# 内容呈现规范

让内容自身形成版式。先识别内容语义，再决定视觉形式，不用 Card、边框或 Glass 把所有东西包装成同一种组件。

## 工作流程

1. 识别页面内容模型：文章、作品、短记、链接、代码、媒体、引用、数据或混合内容。
2. 建立语义结构和阅读顺序，再决定组件。
3. 给每种内容类型分配合适的空间层级：阅读列、宽内容列、舞台列或 overlay。
4. 让辅助信息保持低权重；不要与正文持续竞争。
5. 使用 `perceptual-reading` 校验正文舒适度，使用 `adaptive-layout` 校验不同容器中的重排方式。
6. 只有在内容结构清楚后，才用 `apple-design` 添加材质、色彩和品牌表达。

## 内容不变量

- 文章不是 Dashboard。不要把标题、作者、目录、段落、引用、图片和相关推荐全部做成独立 Card。
- 使用语义 HTML：`article`、`header`、`nav`、`section`、`figure`、`figcaption`、`blockquote`、`code`、`table`、`aside` 等表达内容关系。
- 正文默认保持连续阅读流。只有真正具有独立交互或语义边界的内容才使用 surface/card。
- 图片和图表可以突破正文测量，但图注和相关解释必须保持清晰关联。
- 引用主要通过排版、缩进、字形或轻量背景形成语气变化，不默认套厚重边框卡片。
- 代码块作为技术内容 surface 处理，保持复制、语言标记、滚动和对比度；不要为了适配窄屏把代码字体缩小到不可读。
- 表格保留表头与数据关联；窄屏时允许局部滚动或语义重组，不让整页横向滚动。
- 脚注和参考资料属于阅读辅助层，可用锚点、popover 或末尾注释，但必须保证无 JS 时仍能访问。
- 目录反映标题结构，不为视觉效果制造虚假的层级。
- 元数据、标签和社交操作保持次要；文章首屏优先标题、摘要/导语和正文入口。

## 内容层级

建议把内容空间抽象为：

```text
reading   正文、列表、普通引用
wide      代码、表格、图表、宽图片
stage     需要沉浸呈现的特色媒体/交互作品
ambient   背景装饰，不承载必要信息
```

每种内容进入哪一层由语义决定，不由“看起来酷不酷”决定。

## 设计审查

- 去掉所有 Card 背景后，内容结构是否仍然清楚？
- 每个视觉容器是否都有真实语义或交互理由？
- 图片、代码、表格、引用是否按内容类型得到不同处理？
- 文章标题结构是否能生成正确目录？
- 无 JS 时，核心内容、脚注和链接是否仍可读？
- 分享、标签、作者信息是否抢过正文？
- 相关推荐是否在读完之后出现，而不是打断正文？
