# 认知工效规范

让界面承担更多记忆、解释和状态组织工作，减少用户的短时记忆、决策和恢复成本。

## 核心原则

- **Recognition 优先于 Recall**：能看见、能比较、能识别，就不要要求用户记住并回忆。
- **减少不必要决策**：不要把实现层的选项数量原样暴露给用户。
- **一致性减少重新学习**：同类对象、动作和结果保持稳定命名与行为。
- **渐进披露复杂度**：先显示完成当前任务所需信息，再按需展开高级能力。
- **保持上下文**：切换页面、层级、模式或中断后，应尽量保留用户的当前位置、选择与未完成意图。
- **预防优于纠错**：能通过约束、默认值、实时提示或可撤销设计避免错误，就不要等错误发生后再解释。
- **不要把“简洁”误解为隐藏**：减少认知负荷不是减少可发现性。

## 工作流程

1. 先写出用户当前要完成的核心任务，不从组件开始。
2. 标出用户必须记忆、比较、判断、切换和等待的点。
3. 删除没有实际决策价值的选择；合并等价选项。
4. 将需要记忆的内容外化到界面：可见状态、最近选择、上下文标签、预览或明确默认值。
5. 将复杂能力按任务阶段分层；不要一次展示全部高级选项。
6. 检查术语、位置和行为是否与项目既有心智模型一致。
7. 检查中断、返回、失败或重新进入后，用户是否能快速恢复任务。
8. 如问题来自导航、系统状态或交互语义，转交 `navigation-wayfinding`、`system-feedback` 或 `interaction-affordance`。

## 认知负荷来源

重点识别：

- 同屏过多同权重选择。
- 需要跨页面记忆的数据或状态。
- 隐藏但关键的规则。
- 相同概念使用不同术语。
- 相同外观产生不同结果。
- 频繁模式切换。
- 长流程中丢失进度与上下文。
- 需要先理解系统内部结构才能完成任务。
- 错误发生后没有明确恢复路径。

## 决策设计

- 主要任务区域避免同时出现多个同等强度主操作。
- 默认值应表达合理常见路径，但不能替用户做不可逆决定。
- 将“是否需要做”与“怎么做”的决策分层，避免一次要求用户回答多个问题。
- 相似选项优先支持直接比较，不要求用户在不同页面间来回记忆。
- 高级设置允许隐藏，但入口应稳定、可预测且不会改变核心结果的可理解性。

## 记忆与上下文

- 优先显示当前状态、当前位置、已选择项和下一步，而不是让用户回忆上一屏。
- 返回上一步时尽量保留滚动位置、输入、筛选和选择，除非安全或数据一致性要求必须清空。
- 不依赖颜色、图标或位置单独承载必须记住的业务规则。
- 跨步骤流程使用持续可见的任务上下文，不让用户重新推断“我做到哪了”。

## 渐进披露

按以下顺序判断：

```text
当前任务必须知道
→ 当前阶段可能需要
→ 高级 / 少数场景
→ 专家级 / 低频能力
```

- 第一层直接可见。
- 第二层可在当前上下文内展开。
- 后两层允许进入二级界面或高级区域。
- 不把关键风险、价格、权限、不可逆影响藏进高级区域。

## 边界

- 内容语义与内容类型：`content-presentation`。
- 阅读舒适与视觉负荷：`perceptual-reading`。
- 页面/组件位置变化：`adaptive-layout`。
- 空间关系与视觉重心：`spatial-composition`。
- 全局导航与当前位置：`navigation-wayfinding`。
- 控件可点击性与状态 signifier：`interaction-affordance`。
- 加载、成功、失败、撤销与恢复反馈：`system-feedback`。
- 可访问性约束：`inclusive-accessibility` 横向覆盖。
