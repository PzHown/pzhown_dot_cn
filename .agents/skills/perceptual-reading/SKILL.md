# 感知阅读规范

把“读得舒服、看得明白、长时间不累”设为博客设计的最高约束。不要把阅读体验等同于固定字号或固定 `65ch`；根据语言、内容类型、容器宽度、输入方式和设备环境共同决定排版。

## 工作流程

1. 先识别内容：中文、英文、中英混排、代码、表格、图片、脚注、长文或短内容。
2. 先建立阅读层，再建立装饰层：确定正文宽度、字号、行高、段落节奏、标题层级和前景/背景对比。
3. 检查视觉负荷：降低正文周围无关高对比元素、重复边框、持续动画和透明材质竞争。
4. 检查跨设备阅读：窄屏、平板、宽屏不能只同比缩放；保持相同信息优先级，但允许不同排版参数和辅助导航形式。
5. 检查 200% 文本缩放、浏览器缩放、深色模式、系统字体替换、长标题和中英文混排。
6. 最后才允许调用 `apple-design` 增强视觉语言，调用 `interaction-motion` 增强状态与空间连续性。

## 阅读不变量

- 让正文成为视觉权重最高且最稳定的区域；导航、标签、元数据和装饰不得长期争夺注意力。
- 不使用单一“最佳行长”覆盖所有语言。中文按实际字形、字号和容器评估；英文可参考字符测量，但不得把 `65ch` 当硬规则。
- 宽屏不等于正文变宽。把额外空间用于目录、注释、媒体或留白，而不是无限延长一行文本。
- 用字号、字重、行高、段距和留白建立阅读节奏，避免靠大量分割线和卡片边框组织文章。
- 正文背景保持稳定。不要让强渐变、动态光斑或高强度 backdrop blur 位于持续阅读文字之后。
- 深色模式降低眩光但不追求纯黑极端对比；保持文字清晰，同时避免细字和低对比灰字。
- 不用颜色作为唯一信息编码。链接、重点、警告、选择状态需要形状、文字或其他冗余线索。
- 支持用户缩放和系统字体；不要用固定高度裁切正文，不要阻止浏览器缩放。
- 中文标点、英文单词、数字、代码和链接混排时，优先保证断行自然，避免狭窄列产生连续孤字/孤词。
- 阅读核心区域优先静态渲染和轻量 CSS，避免为视觉效果引入不必要 React hydration。

## 文章排版策略

- 把正文列、宽媒体列和全宽舞台分成不同空间层级，不要让所有内容使用同一个最大宽度。
- 标题与正文的尺度关系应随容器流体变化，但保持清楚的层级跳跃。
- 段落之间用节奏分组；连续短段不额外套 Card。
- 代码、表格、图片、引用和脚注按内容类型独立处理；具体规则读取 `references/implementation.md`。
- 目录属于阅读导航，不应永久压缩手机正文；在窄屏转为轻量入口或折叠层。

## 设计审查

完成阅读相关任务前检查：

- 第一眼是否先看到内容，而不是 UI 框架？
- 连续阅读 5 分钟时，是否存在持续抢注意力的动画、边框、色块或玻璃？
- 宽屏正文是否过长，窄屏每行是否过短？
- 标题、正文、引用、注释、代码能否快速区分？
- 200% 缩放后是否仍可阅读且不出现横向页面滚动？
- 中文、英文和中英混排是否都自然？
- 深色模式是否避免刺眼、糊成灰或对比不足？
- 元数据和辅助操作是否低于正文权重？

本 Skill 主要降低视觉阅读负担；如果问题是选择太多、需要记忆、模式切换或流程难理解，使用 `cognitive-ergonomics`。
